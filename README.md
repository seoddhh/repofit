# RepoFit

**내 레포에 딱 맞는 오픈소스, 적용 방법까지.**

*Find the right open source for your repo.*

RepoFit은 GitHub의 트렌딩 오픈소스와 사용자의 프로젝트를 함께 분석해, 프로젝트에 도움이 될 도구를 추천하고 구체적인 적용 방법을 안내하는 AI 에이전트 플랫폼입니다.

에이전트가 프로젝트의 기술 스택과 구조를 파악하고, 후보 오픈소스의 문서와 코드를 확인해 **왜 필요한지, 어디에 적용할지, 어떻게 검증할지**를 설명합니다.

> 현재 상태: UI와 실제 GitHub Trending·공개 레포 자료 조회, 규칙 기반 적용 검토, Sites 기반 ChatGPT 로그인·계정 화면을 구현했습니다. 모델 추론·사용자 플랜 연동·서버 기록 저장은 준비 중입니다. 실행 방법은 [DEVELOPMENT.md](./DEVELOPMENT.md), 배포·인증과 플랜 지원 검토는 [DEPLOYMENT.md](./DEPLOYMENT.md)를 참고하세요. 아래 내용은 제품 비전과 목표 범위를 설명합니다.

## 왜 RepoFit인가

새로운 오픈소스는 계속 등장하지만, 인기가 있다는 이유만으로 내 프로젝트에 유용한 것은 아닙니다. 개발자는 도입 여부를 판단하기 위해 문서, 호환성, 유지보수 상태, 실제 적용 위치를 직접 확인해야 합니다.

RepoFit은 이 탐색과 검토를 도와 다음 질문에 답합니다.

- 내 프로젝트에 지금 도움이 될 오픈소스는 무엇인가?
- 이미 사용 중인 라이브러리와 기능이 겹치거나 충돌하지 않는가?
- 도입하면 어떤 문제를 해결하고, 어떤 부담이 생기는가?
- 어떤 파일부터 바꾸고, 적용 결과를 어떻게 확인해야 하는가?

## 사용 흐름

1. **ChatGPT로 로그인** — 계정을 연결하고 분석 기능의 사용 권한을 확인합니다.
2. **프로젝트 선택** — GitHub 레포 URL을 입력합니다. 초기 버전은 공개 레포를 우선 지원합니다.
3. **개선 목표 입력** — 성능, 테스트, UI, 개발 생산성 등 원하는 방향을 적습니다. 목표 없이 전체 분석을 시작할 수도 있습니다.
4. **프로젝트 분석** — README, 의존성 목록, 디렉터리 구조, 관련 소스 파일을 확인합니다.
5. **오픈소스 검토** — 트렌딩 후보의 공식 문서와 레포를 조사하고 프로젝트와의 적합성을 비교합니다.
6. **추천 확인** — 추천 이유, 기대 효과, 도입 난이도, 주의점, 근거 링크를 확인합니다.
7. **적용 가이드 생성** — 선택한 후보의 설치 방법, 수정 위치, 예제 코드, 검증 절차를 받습니다.

초기 버전의 결과물은 추천 보고서와 적용 가이드입니다. 레포에 코드를 직접 반영하거나 PR을 생성하는 기능은 후속 범위로 둡니다.

## 핵심 기능

| 기능 | 제공할 내용 |
| --- | --- |
| 프로젝트 분석 | 언어, 프레임워크, 의존성, 구조, 개선할 지점 요약 |
| 트렌딩 탐색 | 기간·언어별 후보 탐색, 출처와 수집 시점 표시 |
| 후보 검증 | 공식 문서, 주요 코드, 릴리스, 라이선스, 유지보수 상태 확인 |
| 맞춤 추천 | 프로젝트의 실제 필요와 호환성을 바탕으로 우선순위 제시 |
| 대안 비교 | 현재 구성 유지와 다른 후보를 포함한 장단점 비교 |
| 적용 가이드 | 설치, 설정, 파일별 변경 제안, 예제 코드, 검증 및 되돌리기 방법 |
| 분석 기록 | 프로젝트별 보고서와 사용자가 선택한 추천 저장 |

## 에이전트의 분석 방식

```text
프로젝트 URL + 개선 목표
          ↓
프로젝트 구조와 의존성 분석
          ↓
트렌딩 기반 후보 수집 및 필터링
          ↓
후보의 공식 문서와 코드 검토
          ↓
호환성·효용·도입 비용 비교
          ↓
근거가 있는 추천 보고서
          ↓
선택한 오픈소스의 적용 가이드
```

각 단계는 분석 작업의 구분이며, 특정 에이전트 프레임워크나 여러 에이전트의 동시 실행을 전제하지 않습니다.

### 추천 기준

- **프로젝트 적합성:** 현재 스택과 버전에 맞고, 실제 개선 목표를 해결하는가?
- **도입 효과:** 얻는 이점이 기존 구성 유지보다 충분한가?
- **도입 비용:** 설정, 마이그레이션, 학습, 운영 부담이 어느 정도인가?
- **중복과 충돌:** 기존 의존성과 역할이 겹치거나 구조 변경이 필요한가?
- **프로젝트 상태:** 문서, 릴리스, 유지보수 활동을 확인할 수 있는가?
- **라이선스와 제약:** 라이선스 정보를 확인할 수 있고 사용 조건 검토가 필요한가?

트렌딩은 후보를 찾는 신호로 사용합니다. 최종 추천에서는 인기도보다 프로젝트 적합성과 도입 효과를 우선합니다. 적절한 후보가 없다면 추가 도입이 필요하지 않다는 결과도 제공합니다.

### 근거 제공 원칙

- 프로젝트 분석은 확인한 파일 경로와 분석 대상 커밋을 근거로 설명합니다.
- 후보 분석에는 문서·레포 링크, 확인한 버전 또는 커밋, 확인 시점을 남깁니다.
- 실제로 확인한 사실과 에이전트의 추론을 구분합니다.
- 접근할 수 없는 코드나 확인하지 못한 호환성을 검증 완료로 표시하지 않습니다.
- 적용 예제는 변경 제안으로 표시하고, 실제 실행 검증 여부를 함께 알립니다.

## 결과물 예시

다음은 출력 형식을 설명하는 가상 예시이며 실제 분석 결과가 아닙니다.

```text
프로젝트: React + TypeScript 웹 앱
개선 목표: 서버 데이터의 로딩·오류 처리 일관성 개선

추천 후보: 서버 상태 관리 라이브러리
추천 이유: 여러 화면에 요청 상태 처리 코드가 반복됨
적용 위치: 데이터 요청 모듈과 이를 사용하는 화면
기대 효과: 로딩·오류 처리와 캐시 정책을 공통화
도입 난이도: 중간 — 기존 요청 흐름을 점진적으로 변경
주의점: 현재 의존성과의 역할 중복 및 버전 호환성 확인

적용 가이드:
1. 호환 버전과 필요한 의존성 확인
2. 공통 설정 추가
3. 화면 한 곳에 먼저 적용
4. 로딩·오류·재요청 동작 검증
5. 결과 확인 후 적용 범위 확대

근거: 확인한 프로젝트 파일, 후보 문서, 버전, 확인 시점
```

## 초기 개발 범위

MVP는 **공개 레포 하나에서 유용한 추천과 적용 가이드를 얻는 경험**에 집중합니다. 아래 범위는 초기 제안이며 구현 과정에서 조정할 수 있습니다.

- [ ] 레포 URL과 개선 목표 입력 화면
- [ ] 공개 레포의 구조·의존성·관련 소스 분석
- [ ] 트렌딩 후보 수집과 출처·수집 시점 관리
- [ ] 후보 오픈소스의 문서·코드 검토
- [ ] 우선 추천 후보 3~5개와 근거 제공
- [ ] 선택한 후보의 프로젝트별 적용 가이드
- [ ] 분석 진행 상태, 실패 원인, 재시도 화면
- [x] ChatGPT Sites 로그인 경로·계정 상태 연동
- [ ] 사용자 플랜·크레딧 사용의 지원 범위 확인 및 연동 검증
- [ ] 사용자별 분석 기록 저장
- [ ] ChatGPT Sites 배포

비공개 레포 연결, 자동 코드 수정·PR 생성, 주기적 추천 알림, 팀 기능은 후속 확장 후보입니다.

## 로그인, 사용량, 배포

### ChatGPT 로그인

서비스 계정은 **Sign in with ChatGPT**를 기반으로 설계합니다. ChatGPT 계정 인증과 GitHub 레포 접근 권한은 별개로 취급합니다.

ChatGPT Sites는 공개 사이트에 로그인 기능을 추가하는 방식을 제공합니다. 인증된 사용자 정보에 따른 접근 제어는 서버에서 처리합니다. 구체적인 연동 방식은 [공식 Sites 문서](https://learn.chatgpt.com/docs/sites?surface=app)를 기준으로 구현합니다.

### 사용자 플랜과 크레딧

제품 목표는 사용자가 본인의 ChatGPT 플랜에 포함된 사용량 또는 사용 가능한 크레딧으로 AI 분석을 실행하는 것입니다.

로그인만으로 사용량 접근 권한을 얻는 것은 아닙니다. ChatGPT plan usage는 별도의 선택 권한이며, 사용자 동의와 지원되는 실행 환경이 필요합니다. [공식 통합 안내](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)를 참고합니다.

**확인 필요:** 공식 문서는 오픈소스·로컬 호스팅 앱의 플랜 사용을 안내하며, 원격 호스팅 또는 유료 앱에는 별도 참여 절차를 안내합니다. 따라서 Sites 로그인만으로 방문자의 크레딧을 사용할 수 있다고 가정하지 않습니다. RepoFit의 실제 배포 환경에서 지원 여부와 연동 경로를 확인한 뒤 기능을 활성화합니다. [ChatGPT plan usage 문서](https://developers.openai.com/siwc/token-sharing-open-source)

지원 여부가 확정되기 전에는 사용자 크레딧 사용을 완료된 기능으로 표시하지 않습니다. 분석 시작과 추가 가이드 생성 등 사용량이 발생하는 동작을 명확히 안내하고, 권한 거부·사용 한도 도달·연결 만료 상태를 처리합니다.

### 배포 방향

ChatGPT Sites를 통해 호스팅하고, 플랫폼이 제공하는 사이트 주소를 사용합니다. 프로젝트를 등록하고 소유자 전용 비공개 배포를 준비했습니다. 배포 결과와 실제 인증 검증 상태는 작업 결과 및 [배포 검토](./DEPLOYMENT.md)를 참고하세요.

## 데이터 처리와 접근 범위

- 초기 분석은 공개 레포를 읽는 방식으로 시작합니다.
- 저장소 콘텐츠는 분석 자료로 취급하며, 그 안의 지시문을 서비스의 실행 지시로 따르지 않습니다.
- 프로젝트 코드를 실행하거나 의존성을 설치하는 검증은 초기 분석에 포함하지 않습니다.
- 분석에 필요한 파일을 우선 수집하고, 비밀키·환경 변수 파일 등 민감한 파일은 수집 대상에서 제외합니다.
- 분석 결과와 기록은 사용자별로 분리하고, 조회 권한을 서버에서 확인합니다.
- 비공개 레포 지원 시에는 별도 GitHub 권한 연결과 분석 범위 안내를 추가합니다.
- 저장 항목, 보관 기간, 삭제 방식은 기록 저장 기능 구현 전에 확정해 안내합니다.

## 개발 상태와 다음 단계

React·TypeScript·Tailwind와 Vinext/Vite 기반 로컬 앱을 구현했습니다. 실제 트렌딩 조회, 내 레포 입력과 구조 확인, 오픈소스 적용 검토 UI를 제공합니다. 실행 명령과 데이터·추론 연결 범위는 [개발 안내](./DEVELOPMENT.md)에 정리했습니다.

다음 개발에서는 배포 환경의 제약과 사용자 플랜 사용 지원 여부를 먼저 확인하고, 공개 레포를 대상으로 분석부터 추천·적용 가이드까지 이어지는 최소 기능을 구현합니다. 트렌딩 데이터 수집 방식과 갱신 주기도 이 단계에서 확정합니다.

프로젝트 라이선스는 아직 정하지 않았습니다. 공개 및 기여 정책을 정할 때 `LICENSE`와 기여 안내를 추가합니다.
