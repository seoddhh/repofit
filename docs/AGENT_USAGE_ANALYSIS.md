# RepoFit 스킬 기반 에이전트 활용 분석

기본 흐름은 사용자에게 설문·목표·분석 조건·후보 스킬을 요구하지 않는다. 사용자 에이전트가 RepoFit의 `repofit-usage-analysis` 스킬을 실행해 접근 가능한 작업 기록에서 사용 방식과 개선 기회, 필요한 기능을 도출하고 실제 카탈로그 후보를 비교해 보고서를 작성한다. Mac 페어링은 기본 경로의 전제 조건이 아니다.

## 실행과 UI

에이전트에서 “RepoFit으로 내 에이전트 활용 분석해 줘”라고 요청하면 `start_usage_analysis`로 시작할 수 있다. 분석과 근거 요약·결과의 30일 보관에 대한 요청이 있어야 `consent: true`를 사용한다. 로그인만으로 모든 과거 기록을 읽을 수 있는 것은 아니다. 접근 가능한 최근 작업 기록 최대 10개를 사용하며 한 개만 있어도 분석한다. 현재 대화만 읽었다면 그 범위로 한정하고, 자료가 전혀 없으면 실패로 종료한다.

사이트 `/agent`는 다음 상태를 구분한다.

1. **분석 안내와 동의:** 입력 폼 대신 보고서에서 얻을 내용을 안내하고 보관 동의를 받는다.
2. **실행 요청 준비:** 사이트 버튼은 계정 소유의 대기 요청을 만든다. 이 상태를 분석 중이라고 표시하지 않는다. 지원 호스트의 `window.openai.sendFollowUpMessage`가 있을 때만 실행 요청을 전달하고, 일반 웹페이지에서는 에이전트 대화로 보낼 요청을 복사할 수 있다. 이 확장은 MCP UI 호스트용이므로 일반 IAB나 브라우저에서의 자동 시작을 보장하지 않는다.
3. **실제 분석 중:** 사용자 에이전트가 `start_usage_analysis`를 호출했을 때만 running으로 전환한다.
4. **보고서:** 분석 범위·전체 요약·주요 관찰·대표 근거·추천과 활용법을 제공한다. 이전 보고서도 유지한다.

## MCP 계약

- `get_usage_analysis_instructions`: 공통 스킬과 분석·보고서 스키마.
- `start_usage_analysis`: 동의와 선택적인 기존 요청 ID로 시작. 사용자 입력 조건이나 기기 ID가 필요하지 않다. 실행 요청·지침·스키마를 반환한다.
- `submit_usage_analysis`, action `prepare`: 원문 대신 분석 요약과 실제 coverage를 제출하고 관련 카탈로그 후보를 받는다.
- `submit_usage_analysis`, action `complete`: 반환된 후보와 관찰에 근거한 보고서를 제출한다.
- `submit_usage_analysis`, action `fail`: 자료 없음·조회 실패·실행 실패로 종료한다.
- `list_usage_analyses`, `get_usage_analysis`: 본인 기록 조회.

제출은 반환된 최신 `revision`으로 수행한다. 서버는 Sites 호출자 신원으로 소유권을 확인한다. 사용자 ID를 입력으로 받지 않는다. 다른 계정·구형 revision·중복 시작·종료·취소·만료된 요청은 제출할 수 없다. 사용자별 직접 실행은 활성 한 건이고 대기 요청 준비는 멱등적이다. 준비 후 30분 내 시작하지 않거나 실행 중 30분 동안 단계 전환이 없으면 실패로 만료된다. 요청·결과의 저장 기간은 30일이다.

사이트의 브라우저 도구는 동일한 MCP 검증과 저장 함수를 사용한다. 페이지를 열어 둔 에이전트는 페이지 도구로도 이 계약을 실행할 수 있다. 도구 노출 자체가 대기 중인 Codex를 시작하는 실행 기능은 아니다.

## 판단과 근거

`workflow-evidence-v1` 기준으로 목표·문맥, 작업 연속성, 범위, 검증, 반복 절차 중 해당하는 관점을 적용한다. 주요 판단 최대 5개에 상태, 원인과 관련된 구간(추정), 확인한 영향·미확인 사항, 다른 해석, 다음 확인 방법을 붙인다. 모든 항목을 주석으로 출력하지 않고 판단별 대표 근거 1~3개에 유형과 최대 160자 요약을 붙인다. 자료 부족·해당 없음은 스킬 탐색·추천 근거로 사용하지 않는다. 부족한 점을 억지로 만들거나 사용자 숙련도를 채점하지 않는다.

직접 실행의 근거 요약과 유형은 사용자 에이전트가 보고한다. 서버는 스키마, 사례 범위, 관찰·후보 참조를 검사하지만 원문과 의미를 대조하거나 인과관계를 증명하지 않는다. coverage의 `verification`은 서버가 `agent_reported`로 저장한다. 에이전트가 `local_checked`를 보내도 이를 신뢰하지 않는다. 보고서와 Markdown에도 이 차이를 표시한다.

## 기존 로컬 실행 대안

`npm run local-agent -- --site https://repofit.seoddh.chatgpt.site --agent codex --usage-analysis`는 기존 페어링 기기 방식으로 유지한다. `request_usage_analysis`는 이 대안용이며 기본 웹 UI에서는 사용하지 않는다. 기기 인증 `/api/local-agent/usage-mcp`의 claim·heartbeat·prepare·complete 계약은 유지된다.

이 대안은 App Server로 최근 대화 일부를 수집하고 새 Codex를 두 번 실행한다. 원본 ID와 근거 유형을 로컬에서 대조한 뒤 `local_checked`로 저장한다. 원문·명령 출력은 사이트에 보내지 않는다. 모든 비밀값 탐지를 보장하지는 않으며, 사용자 Codex 모델 서비스에 입력이 전달될 수 있다.

## 저장과 검증

`agent_usage_runs`의 executor가 `agent`이면 deviceId는 null이다. 기존 요청은 `local`로 유지한다. 0008 마이그레이션은 기존 기록을 보존하면서 기기 없는 실행을 지원한다. 과거 마이그레이션은 변경하지 않는다.

`node scripts/verify-usage-analysis.mjs`는 실제 모델과 사용자 대화 대신 가짜 자료로 직접 MCP 실행 전체, 조건 없는 요청, 소유권·동의·단일 시작·revision·취소·자료 없음, 근거 출처 표시, 추천 검증, 구형 보고서·마이그레이션 보존, 기본 UI, 기존 로컬 실행 계약을 검증한다. 실제 호스트의 자동 실행 전달과 사용자 기록 접근은 해당 환경에서 별도로 확인해야 한다.
