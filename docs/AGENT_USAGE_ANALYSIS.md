# 에이전트 활용 분석 실행과 MCP 연결

`/agent`의 기본 흐름은 사용자의 최근 Codex 작업을 분석한다. 사이트에서 비교할 스킬을 고르거나 후보 없이 분석을 시작할 수 있다. 선택 후보가 있으면 다른 검색 결과로 대체하지 않는다. 기존 설문은 `/agent?mode=questionnaire`에서 유지한다.

## 사용 방법

1. RepoFit에 로그인하고 **Mac 연결과 내 스킬 목록**에서 일회용 코드를 만든다.
2. 최신 RepoFit 소스 폴더에서 `npm ci` 후 다음 명령을 실행하고 연결 코드를 입력한다.

```sh
npm run local-agent -- --site https://repofit.seoddh.chatgpt.site --agent codex --usage-analysis
```

3. 프로그램을 켜 둔 상태에서 사이트의 최근 대화 분석·보관 안내를 확인하고 **내 Codex로 분석 시작**을 선택한다. 로컬 Codex CLI 설치·로그인과 본인 이용 한도가 적용된다.

새 Codex 실행 자체는 기존 대화를 기억하지 않는다. 연결 프로그램이 App Server의 `thread/list`, `thread/items/list`로 최근 로컬 대화 최대 10개를 읽어 전달한다. 보관된 기록이나 다른 기기·클라우드에만 있는 기록을 읽었다고 가정하지 않는다. 대화별 최근 항목 최대 200개에서 지원 항목 최대 40개, 약 6,000자까지 고른다. 요청·응답·명령·도구 상태 일부를 포함하고 명령 출력·인증 파일은 제외한다. 흔한 인증값 형식은 제거하지만 모든 민감한 정보의 자동 탐지를 보장하지 않는다. 입력은 사용자의 Codex 모델 서비스에 전달될 수 있다.

## 실행 구조

```text
사이트의 선택 후보·실행 동의 → 사용자·기기에 배정된 DB 요청
→ 연결 프로그램이 MCP로 작업 claim
→ 최근 대화 일부를 로컬에서 준비
→ 새 Codex: 활용 방식과 필요한 기능 분석
→ 로컬에서 원본 근거 ID 검증
→ MCP prepare: 근거 요약 제출·카탈로그 후보 수신
→ 새 Codex: 사용 방식과 스킬 적합성 비교
→ MCP complete: 결과 검증·저장 → 사이트에서 조회
```

`agent_usage_runs`에는 요청, 분석 요약, 확인 범위, 당시 후보 설명과 결과를 30일 보관한다. 원문 대화 ID·제목·대화 원문·명령 출력은 서버에 보내지 않는다. 사례·항목 수와 잘린 범위, 조회 실패를 표시한다. 에이전트가 작성한 관찰과 해석이며 실행 호환성이나 추천 효과를 독립적으로 검증한 결과는 아니다. 사용자가 결과를 내려받거나 삭제할 수 있고 만료 기록은 분석 API 사용 시 정리된다.

완료된 기록은 보고서 화면으로 연다. 분석 범위와 관찰·추천 수, 핵심 요약을 먼저 보여주고 관찰별 사실·해석·필요 기능과 근거를 펼쳐 확인한다. 추천 카드에서 관련 관찰로 이동할 수 있으며 기대 변화, 기존 스킬과의 관계, 적용 순서와 확인 기준을 구분한다. 예시 요청을 복사하고 Markdown 보고서를 내려받을 수 있다. JSON은 분석 근거 영역에서 별도로 제공한다.

### 판단과 근거 표시

새 분석은 `workflow-evidence-v1` 기준으로 목표·문맥, 작업 연속성, 범위, 검증, 반복 절차 중 해당하는 관점을 적용한다. 주요 판단 최대 5개에 판단 상태, 원인과 관련된 구간(추정), 확인한 영향·미확인 사항, 다른 해석, 다음 확인 방법을 붙인다. 모든 대화 항목을 주석으로 출력하지 않고 판단별 대표 근거 1~3개만 유형과 최대 160자 요약으로 보여준다. 전체 요약도 이 근거에서 도출하며 근거가 없으면 자료 부족으로 표시한다.

대표 근거의 ID가 실제 읽은 항목 및 해당 관찰의 `sourceIds`에 있는지, `kind`가 로컬에서 수집한 사용자 요청·에이전트 응답·명령·도구 유형과 일치하는지 전송 전에 확인한다. 이는 원인의 인과관계나 요약 내용의 진실성을 독립적으로 검증한 것은 아니다. 사용자에게 책임이나 숙련도 점수를 부여하지 않는다. `insufficient_evidence`, `not_applicable`인 관찰로는 스킬을 탐색하거나 추천하지 않는다. 사용자가 지정한 후보는 그대로 검토하지만 충분한 다른 근거가 없으면 추천을 비운다.

대표 근거 생성은 기존 첫 번째 모델 실행에서 처리한다. 두 번째는 그 판단 요약을 재사용하되 `sourceIds`와 대표 근거 목록을 제외해 중복 입력을 줄인다. 모델 호출·대화 수집량은 늘지 않지만 입력 지침과 출력 요약이 늘어 토큰·지연이 증가할 수 있다. 생성 스키마에서 판단 수와 텍스트 길이를 제한한다. 화면에서 접는 기능은 읽기 편의를 위한 것이며 모델 토큰을 줄이지 않는다. 실제 모델의 추가 토큰과 지연은 별도 실행 측정이 필요하다. 구형 보고서는 기준·판단 필드가 없음을 표시하고 기존 내용으로 열며 새 판단을 임의로 채우지 않는다. 저장 데이터가 JSON이므로 이 변경에는 추가 DB 마이그레이션이 없다.

사이트는 Sites 사용자 ID로 본인 기록만 조회한다. 연결 프로그램은 기존 페어링 기기 토큰으로 배정된 작업만 처리한다. 토큰과 작업 lease는 해시로 저장한다. 기기별 활성 분석은 한 건으로 제한한다. 취소·삭제·연결 해제·lease 만료 후 결과는 받지 않는다. 연결 프로그램은 10초 heartbeat로 중단을 확인한다.

## MCP 경로

| 경로 | 인증 | 기능 |
| --- | --- | --- |
| `/mcp` | Sites 호출자 신원, 개인 기록은 사용자 ID 필수 | 지침·카탈로그 검색, 본인 분석 목록·결과, 연결 기기에 실행 요청 |
| `/api/local-agent/usage-mcp` | 메모리에 보관한 페어링 기기 토큰 | 지침·검색, 배정 작업 claim, lease 기반 heartbeat·prepare·complete·fail |

두 경로는 같은 저장·검증 함수를 사용한다. 자동 실행에서는 연결 프로그램이 MCP 클라이언트 역할을 맡고 모델에는 자료만 전달한다. 사용자의 전역 Codex MCP 설정을 수정하거나 모델에 기기 토큰을 전달하지 않는다.

일반 사용자 Codex에서 직접 도구를 쓰려면 Sites의 RepoFit 플러그인을 설치·연결해 `get_usage_analysis_instructions`, `search_usage_skills`, `list_usage_analyses`, `get_usage_analysis`, `request_usage_analysis`를 사용할 수 있다. 플러그인 접근·공유는 플랫폼 권한에 따른다. 웹사이트 로그인만으로 설치된다고 표시하지 않는다.

지침 원본은 `public/skills/repofit-usage-analysis/SKILL.md`와 같은 폴더의 단계별 JSON 스키마다. 로컬 실행과 MCP 지침 조회가 이 문서를 공유한다. 기존 프로젝트 검토의 페이지 도구 흐름은 별도다.

## 검증과 배포

`node scripts/verify-usage-analysis.mjs`는 임시 SQLite, 가짜 기록 조회와 모델 실행을 사용해 사용자·기기 격리, 동의, 단일 claim, 취소·만료·연결 해제, 근거·후보 검증, 원문 비전송을 검사한다. 기존 local-agent, agent-coach, briefs 검증과 `npm run typecheck`, `npm run build`도 실행한다. 실제 CLI·모델 실행, 브라우저 표시, 운영 환경의 인증과 도구 발견은 별도로 확인한다.

새 0007 마이그레이션을 포함해 배포하며 기존 마이그레이션은 변경하지 않는다.
