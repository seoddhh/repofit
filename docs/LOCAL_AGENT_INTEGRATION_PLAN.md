# 로컬 레포·에이전트 연동 계획

작성: 2026-10-18. 상태: 설계 초안. 사용자 선택: **Codex와 Claude Code 동시 지원**.

## 제품의 완료 기준

사용자가 RepoFit에서 자신의 기기를 연결하고 레포와 에이전트를 선택하면 실제 로컬 구성에 근거한 스킬 목록과 도입 후보가 나온다. 추천 항목은 추가되는 작업, 기존 구성과 중복·충돌, 변경할 파일을 설명한다. 사용자가 변경안을 확인해 적용하면 로컬에 반영되고 다시 조회한 결과가 사이트에 표시된다. 요청 프롬프트나 JSON을 매번 복사할 필요가 없어야 한다.

설치 파일이 존재하는 것, 해당 에이전트가 사용할 수 있는 것, 실제로 호출한 것은 구분한다. 사용 기록을 확인하지 못한 항목에 사용 중이라는 표시를 붙이지 않는다.

## 현재 구현과의 차이

- `components/agent-provider.tsx`의 작업·결과는 현재 탭 메모리에만 존재한다. 새로고침 복원과 기기 간 전달이 없다.
- `lib/agent-review.ts`의 프로젝트 요청은 레포와 후보를, 스킬 요청은 직접 입력한 에이전트 이름과 스킬 문자열을 받는다. 레포·에이전트·실제 설치 목록을 함께 담는 분석 문맥이 필요하다.
- `lib/agent-tools.ts`는 브라우저에서 요청·진행·결과를 교환한다. 로컬 에이전트를 실행하거나 목록을 조회하지 않는다.
- `public/skills/repofit-review/SKILL.md`는 검토 절차를 제공한다. 연결 프로그램, 파일 접근 권한, 설치 실행 기능을 대신하지 않는다.
- 현재 D1에는 공개 해설 테이블만 있다. 개인 기기·프로젝트·스킬 목록·실행 결과는 공개 해설과 분리해야 한다.

## 사용자 흐름

1. **기기 연결:** 로컬 연결 프로그램을 한 번 설치·실행하고 로그인한 사이트와 일회용 코드로 연결한다. 연결 대상 계정·기기·허용 범위를 확인한다.
2. **레포 선택:** 로컬 프로그램에서 사용자가 폴더를 선택한다. 사이트에는 프로젝트 이름, 기술 스택, 브랜치, 검사 시점이 나타난다. GitHub 주소 입력만으로 PC의 폴더 접근 권한이 생기지는 않는다.
3. **에이전트 선택:** 탐지한 Codex·Claude Code의 버전, 실행 가능 여부와 인증 상태를 표시한다. 같은 레포에 대해 두 에이전트의 스킬 구성을 비교할 수 있다.
4. **내 구성 보기:** 프로젝트·개인·플러그인 범위의 스킬을 표시한다. 이름·설명·출처·사용 가능 상태·최근 확인 시각을 확인하고 중복 후보를 펼쳐 볼 수 있다.
5. **추천 분석:** 목표를 선택하면 실제 프로젝트 구성과 설치 목록을 기준으로 후보를 검토한다. 진행·중단·실패·완료 상태가 사이트에 돌아온다.
6. **변경안 확인:** 스킬 설치는 설치 대상 에이전트와 범위, 출처 커밋, 추가·수정할 파일을 보여 준다. 프로젝트 도입은 코드 diff, 의존성·설정 변경, 검증 계획을 보여 준다.
7. **적용·확인:** 사용자가 선택한 변경만 로컬에서 반영한다. 재조회로 설치 인식을 확인하고, 실행하지 않은 테스트는 미실행으로 표시한다. 되돌리기도 제공한다.

## 연결 구조

`RepoFit 웹 화면 ↔ 사용자별 작업 API·DB ↔ 로컬 연결 프로그램 ↔ Codex / Claude 어댑터 ↔ 허용한 레포·스킬 경로`

- 로컬 프로그램이 사이트에 HTTPS로 접속해 작업을 가져오는 구조를 우선 사용한다. 브라우저에서 PC의 임의 포트나 파일에 직접 접근하는 방식을 전제로 하지 않는다.
- 최초 버전은 macOS에서 검증 가능한 CLI 연결 프로그램으로 시작한다. 배포할 패키지명·설치 명령은 아직 정하지 않았으며 존재하는 패키지처럼 안내하지 않는다. 설치 후에는 사이트 버튼으로 요청한다.
- 계정·기기·프로젝트마다 작업 범위를 묶는다. 연결 키는 취소 가능하고 읽기·분석·적용 권한을 구분한다. 다른 사용자의 작업과 결과를 조회할 수 없어야 한다.
- 원본 레포와 스킬 본문은 우선 로컬에서 분석한다. 사이트에는 사용자가 허용한 목록·요약·추천·diff·검증 결과를 보낸다. 에이전트의 모델 호출에 어떤 정보가 전달되는지도 연결 화면에 설명한다.
- 서버가 보낸 임의 셸 명령을 실행하는 API는 만들지 않는다. 목록 조회, 분석 시작, 변경안 생성, 승인된 변경 적용처럼 정해진 작업만 처리한다.
- 사이트의 작업 취소가 로컬 실행 중단까지 전달되게 한다. 끊김·재접속·중복 수신 시 같은 설치를 두 번 실행하지 않는다.

공통 어댑터는 `detect`, `inventory`, `analyze`, `cancel`, `verify` 계약을 사용한다. 설치는 공통 변경 계획과 승인 토큰을 사용하되 실제 대상 경로와 형식은 에이전트별로 결정한다. 시작 시 임의의 개인 hooks·MCP 서버가 실행될 수 있는 설정도 확인한다. 읽기 모드라는 프롬프트만으로 실행을 제한하지 않는다.

두 에이전트를 같은 범위로 출시한다. 한쪽 인증·런타임 검증이 실패하면 그쪽을 연결 완료나 분석 지원으로 표시하지 않는다. 현재 열려 있는 데스크톱 대화를 자동으로 장악하는 방식은 전제로 하지 않는다.

## 실제로 수집할 문맥

- **프로젝트:** 로컬 식별자, Git 커밋과 변경 여부, 언어·프레임워크·의존성 버전, 관련 파일 구조, 테스트 구성, 확인 시각. 자격 증명이 포함될 수 있는 원격 URL은 정제한다.
- **스킬:** 에이전트, 이름·설명, 범위, 플러그인 연결, 내용 해시, 출처와 버전, 활성·인식 상태 및 확인 근거. `AGENTS.md`·`CLAUDE.md`·MCP·hooks는 스킬과 별도 구성으로 표시한다.
- **변경 감지:** 스킬 해시·설정·프로젝트 커밋이 바뀌면 스냅샷을 갱신한다. 실행 중인 세션에 즉시 적용되는지 알 수 없으면 재시작·새 세션 필요 상태를 표시한다.
- 전체 홈 폴더, `.env`, SSH 키, 에이전트 토큰, 인증 파일은 수집하지 않는다. 심볼릭 링크는 실제 경로를 확인해 승인한 범위를 벗어나지 않게 한다.

## 추천과 적용의 구체성

후보를 GitHub Trending만으로 고르지 않는다. 공개 해설·공식 저장소·실제 스킬 파일을 후보군으로 삼고, 프로젝트 요구·기존 구성·에이전트 호환성으로 걸러 낸다.

각 후보에 목적, 실제 사용 예시, 현재 어떤 스킬·의존성을 보완하거나 대체하는지, 필요한 외부 도구·권한, 확인한 출처 커밋과 라이선스, 미확인 사항을 연결한다. 스킬 모음, 설치 가능한 플러그인, 프로젝트 라이브러리는 다른 종류로 취급한다. 추천하지 않는 결과도 허용한다.

스킬 적용은 다운로드한 고정 버전의 파일 검토 → 대상 경로와 diff 확인 → 승인 → 임시 경로 검증 → 원자적 반영 → 에이전트 인식 확인 순서로 진행한다. 스킬 스크립트·설치 hooks 실행, 외부 서버 연결은 파일 복사와 별도 권한이다. 기존 스킬을 덮어쓸 때는 사용자 변경을 확인하고 백업·복구 기록을 남긴다.

프로젝트 코드 도입은 별도 변경안으로 처리한다. 의존성 설치·명령 실행은 실행할 내용까지 보여 주고 승인 범위를 묶는다. 승인 후 원본이 바뀌었으면 적용을 중단하고 새 diff를 만든다. Git 커밋·푸시·배포를 적용 버튼에 포함하지 않는다.

## 저장 구조와 기존 코드 변경 방향

- 비공개 데이터 모델: 기기, 프로젝트, 에이전트 프로필, 스킬 스냅샷, 분석 작업, 작업 이벤트, 추천, 변경 계획, 적용·복구 기록. 모든 조회·쓰기에 서버 인증 사용자와 기기 소유권을 확인한다.
- `lib/agent-review.ts`: 레포와 에이전트를 함께 참조하는 작업 문맥을 추가하고, 분석·제안·적용·검증 상태를 분리한다.
- `components/agent-provider.tsx`: 탭 메모리 중심 상태를 서버 작업 조회·이벤트 갱신 구조로 옮긴다. 새로고침 후 복원한다.
- `components/agent-workspace.tsx`: 프롬프트 복사 중심 화면을 연결 상태, 실제 목록, 추천 비교, diff 승인, 실행 결과 중심으로 바꾼다.
- 기존 WebMCP는 선택적인 외부 에이전트 도구로 유지할 수 있다. 제품의 주 실행 경로는 연결 프로그램과 영속 작업 API로 만든다.
- 로컬 연결 프로그램과 두 어댑터는 웹 앱의 Cloudflare 런타임과 분리한다. 사용자 에이전트의 자격 증명은 사이트 DB로 전송하지 않는다.

| 단계 | 결과물 | 완료 확인 |
| --- | --- | --- |
| 0. 양쪽 연동 검증 | 설치 버전·목록·실행·인증·권한의 지원표 | Codex·Claude 각각 실기기 목록과 대조하고 분석 1건을 구조화 결과로 받는다. 인증 경로·비용·자동 hooks 처리의 미해결 항목을 확정한다. |
| 1. 연결과 실제 구성 | 기기 연결, 폴더 승인, 두 에이전트 탐지·스킬 목록 | 임의 수동 입력 없이 내 목록이 보이고, 프로젝트를 바꾸면 목록·범위가 달라진다. 연결 취소와 다른 사용자 접근 차단을 확인한다. |
| 2. 분석과 결과 복원 | 작업 API·이벤트·추천 화면 | 사이트 분석 버튼으로 로컬 작업이 시작되고 결과가 자동 반영된다. 새로고침·취소·오프라인·중복 요청을 처리한다. |
| 3. 스킬 적용 | 대상·diff·승인·설치·인식 확인·복구 | 두 에이전트 모두 테스트용 스킬 추가 후 실제 인식을 확인한다. 중복·사용자 수정·경로 탈출·실패 복구를 확인한다. |
| 4. 프로젝트 적용 | 파일 변경안·선택 적용·검증 결과 | 실제 레포에서 작은 변경 1건을 미리보기부터 적용·검증·복구까지 확인한다. 사용자 수정 파일을 덮어쓰지 않는다. |

첫 화면만 만들고 연동 완료라고 보고하지 않는다. 최소 기능의 첫 검증은 **양쪽 에이전트의 실제 목록을 사이트에서 확인**하는 것이다. 첫 출시 범위에는 분석과 승인된 스킬 적용까지 포함하고, 프로젝트 코드 자동 도입은 다음 단계로 둔다. OS 확장은 macOS 검증 뒤 진행한다.

## 공개 해설 예약의 현재 상태

2026-10-18 조회 결과 사이트의 클라우드 예약 `RepoFit 오픈소스 해설 자동 갱신`은 활성 상태이며 Asia/Seoul 매일 09:17로 설정되어 있다. 수동 게시와 재조회는 검증됐지만, 예약 환경의 무인 수집→작성→게시 성공은 아직 확인되지 않았다. Git 푸시는 이 검증을 대신하지 않는다.

확인할 항목은 예약 환경의 사이트 MCP 인증, 새 조사 스킬의 접근 가능 여부와 실제 적용, 예약 실행 로그, 게시 후 생성 시각·본문 변화다. 로컬에 커밋한 스킬 문서를 클라우드 예약이 자동으로 읽는다고 가정하지 않는다. 예약 지침에 새 스킬을 반영하는 작업은 별도 변경으로 처리한다. 공개 콘텐츠 DB 갱신, 사이트 코드 배포, Git 기록과 로컬 DB 복사는 서로 다른 작업이다.

## 확인한 공식 자료

- [Codex App Server](https://learn.chatgpt.com/docs/app-server): 제품 통합, stdio, 목록·실행·승인 이벤트의 공식 경로. 실험적 전송 방식과 설치 버전 호환성을 확인해야 한다.
- [Claude Code 프로그래밍 실행](https://code.claude.com/docs/en/headless): 구조화 출력, 실행 설정과 자동 로딩 주의점.
- [Claude 스킬](https://code.claude.com/docs/en/skills): 에이전트별 스킬 구조를 확인하는 기준.
- [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview): 실행·승인·세션 기능과 외부 제품 인증 제한. 구독 사용량 재사용을 약속하지 않는다.

이 문서는 구현 계획이다. 작성 과정에서 예약·설치·코드 배포·Git 커밋·푸시를 실행하지 않는다.
