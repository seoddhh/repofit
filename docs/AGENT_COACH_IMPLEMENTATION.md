# 내 에이전트 활용 보고서: 구현과 실행

구현일: 2026-10-27. 기존 `/project` 검토는 유지하며 `/agent`에서 개인 활용 진단과 스킬 보고서를 제공한다. 설계 전체의 자동 설치·복구 단계는 포함하지 않으며, 현재 적용 범위는 가이드·실습·자기 평가까지다.

## 실행

기존 개발 서버와 D1을 사용한다. 기존 마이그레이션 적용 후 새 SQL을 순서대로 로컬 DB에 적용한다. 기존 테이블을 삭제하지 않는다.

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_agent_coach.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0004_agent_activity.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0005_activity_integrity.sql
npm run dev
```

`/agent`에서 로컬 테스트 로그인 후 ‘Codex 연결과 내 스킬 목록’을 펼쳐 연결 코드를 만든다. RepoFit 소스 폴더에서 다음 명령을 실행하고 코드를 터미널에 입력한다.

```sh
npm run local-agent -- --site http://127.0.0.1:5173 --agent codex
```

프로젝트를 선택할 필요가 없다. 연결 프로그램이 개인 작업 폴더와 UUID 프로필을 관리하며 `CODEX_HOME`을 재지정하지 않는다. Codex 실행 파일은 PATH에서 찾는다. 개인 조회에서 프로젝트 범위 스킬은 제외한다. 프로젝트 문맥이 필요할 때만 기존 `--project .` 경로를 사용한다. `--agent claude` / `--agent all`로 개인 목록도 조회할 수 있으며 로컬 보고서 작성은 Codex만 지원한다.

```sh
npm run local-agent -- --agent codex --inspect
```

목록은 App Server의 `skills/list`로 조회한다. 인벤토리 v1은 기존 프로젝트 문맥, v2는 개인 문맥이다. 기존 연결과 스냅샷도 읽을 수 있다. 현재 브라우저의 선택 기기·에이전트를 보고서 입력으로 사용하며, 원하지 않으면 ‘연결된 환경의 스킬 목록을 함께 비교하기’를 해제한다.

## 보고서 생성과 로컬 Codex 작성

관심 작업과 다섯 가지 자가 응답으로 초기 보고서를 만든다. 서버는 모델 호출 없이 규칙 기반 보고서를 먼저 저장한다. 로컬 연결이 없는 사용자도 이 경로를 사용할 수 있으며 실제 행동 분석으로 표시하지 않는다.

연결된 Codex 목록을 포함한 보고서에서는 자료 전달 안내를 확인하고 ‘Codex로 맞춤 보고서 작성’을 요청할 수 있다. 연결 프로그램이 기기 토큰으로 해당 기기의 대기 작업을 가져와 실행한다. 사이트 로그인은 모델 인증을 대신하지 않는다.

보고서 작성은 `codex exec --ignore-user-config --ignore-rules --sandbox read-only --ephemeral` 경로를 사용한다. 기존 Codex 인증은 사용하되 개인 MCP/설정은 로드하지 않는다. 보고서 실행에서는 shell·unified_exec·apps·hooks·스킬 MCP 의존성 설치·웹 검색을 비활성화하고 승인을 자동 허용하지 않는다. 설치 버전이 이 옵션을 지원하지 않으면 실패를 표시하고 초기 보고서를 보존한다. 실제 사용자의 대화를 제어하거나 재개하지 않는다. 입력은 모델 서비스에 전달될 수 있고 로컬 인증·이용 한도가 적용된다.

내부 스킬은 `public/skills/repofit-agent-coach/SKILL.md`, 구조화 출력 계약은 `report.schema.json`이다. 연결 프로그램이 스킬 지침을 보고서 실행 입력에 포함하므로 사용자 전역 스킬 폴더에 추가 설치할 필요가 없다. 모델 결과의 후보 ID·근거 ID·중복 진단 축은 서버에서 검사한다. 이 검사는 사실성·품질 검증 전체를 대신하지 않는다.

작업 lease는 45초, 연결 프로그램 heartbeat는 10초, 실행 제한은 240초다. 취소·기기 연결 해제·lease 만료·보고서 삭제 후 이전 실행자의 결과는 받지 않는다. 실행자 연결이 끊기면 실패로 표시하며 모델 호출을 자동 반복하지 않는다. `--once`는 목록만 한 번 전달하고 분석 대기 작업은 가져오지 않는다.

## skills.sh 연결과 추천 판단

후보는 기존 `/skills`와 같은 공개 검색 API `https://skills.sh/api/search`에서 받는다. 인증이 필요한 `/api/v1`은 사용하지 않는다. 원본과 설치 방법은 카탈로그 링크와 GitHub의 고정 커밋을 참조한다. 출처: [공식 CLI 검색 구현](https://github.com/vercel-labs/skills/blob/main/src/find.ts), [공식 명령 안내](https://github.com/vercel-labs/skills/blob/main/docs/commands.md).

판단은 다음 두 단계다.

1. **규칙 기반 후보 제한:** 관심 작업, 목표에서 찾은 필요 유형, 공유한 사례의 작업 유형을 일반 검색어로 바꾼다. 원문 목표·자기 응답·개인 스킬은 skills.sh에 보내지 않는다. 검색별 후보를 섞어 최대 6개의 원본을 확인한다. 고정 커밋의 `SKILL.md` 이름과 설명이 검색 항목과 일치해야 한다.
2. **로컬 Codex 해석:** 선택한 입력과 확인한 원본만 제공한다. 후보 가운데 적합한 항목 최대 3개 또는 추가 추천 없음을 선택하고, 이유·준비·적용 순서·요청 예시·기대 효과·실습을 작성한다. 제공한 근거와 후보 밖의 ID는 서버가 거부한다.

규칙 버전 1의 내부 적합성 신호는 `관심 작업별 용어 일치 × 30 + 목표의 필요 유형별 일치 × 20 + 목표의 추가 용어 일치(최대 3개) × 5`다. 사용자가 카탈로그에서 선택한 후보가 관련성도 있으면 우선 검토 신호 5를 더한다. 원본 미확인은 0으로 제외한다. 이 값은 사용자 숙련도나 스킬 품질 점수가 아니며 화면에는 점수를 표시하지 않는다. 설치 집계는 계산에 참여하지 않는다.

현재 중복 탐지는 이름을 정규화한 일치 신호다. 동일 내용을 확정하거나 의미상 중복·충돌을 모두 탐지한다고 표시하지 않는다. 해당 신호가 있으면 기존 스킬 활용을 먼저 안내한다. 실행 호환성은 모두 추가 확인 대상으로 표시한다. 원본 본문·필요 도구를 읽은 Codex가 제약을 설명할 수 있지만 실제 설치·실행 테스트를 수행한 것은 아니다.

원본 조회는 GitHub 공개 API를 사용하며 요청 한도가 적용된다. 실패 시 후보를 검증됐다고 표시하지 않고 원인을 안내한다. 원본 조회를 우회하거나 설명을 생성해 대체하지 않는다. 검색과 원본 확인은 제한된 인메모리 캐시를 사용하며 여러 서버 인스턴스 사이의 공유 캐시는 아니다.

## 선택한 과거 사용 사례

```sh
npm run local-agent -- --site http://127.0.0.1:5173 --agent codex --select-history
```

연결 후 터미널에서 최근 로컬 기록 최대 25개 중 하나를 고른다. 목록·제목은 사이트로 보내지 않는다. 선택한 세션에서 최신 항목 최대 200개 중 사용자 요청문, 명령명·종료 코드, 도구 이름·상태만 추출한다. 명령 출력·에이전트 답변·인증 파일은 추출하지 않는다. 현재 Codex 버전이 기록 페이지 조회를 지원해야 한다.

모델 요약에 전달할 수 있는 자료 범위를 안내하고 사용자가 동의했을 때만 실행한다. 모델에 전달하는 선택 요청문·명령 일부는 민감할 수 있으며 ‘로컬 실행이므로 기기 밖으로 전송되지 않는다’고 보장하지 않는다. 생성한 요약을 터미널에서 확인하고 별도로 전송에 동의해야 사이트에 저장된다.

사이트에는 작업 유형, 근거 항목 참조, 진단 축별 요약과 한계만 전송한다. 요약은 추정으로 표시한다. `/agent`에서 공유한 사례를 새로 조회하고 해당 연결의 사례 중 최대 5개를 보고서에 포함할 수 있다. 한 사례로 전체 활용도·반복 패턴·생산성 향상을 단정하지 않는다. 지속적인 수집은 켜지지 않는다.

사례와 보고서는 30일간 조회할 수 있다. 만료 시 조회를 차단하고 다음 관련 API 조회에서 만료된 행을 정리한다. 별도 정기 물리 삭제 스케줄은 아직 연결하지 않았다. 사례를 삭제하거나 사례가 만료되면 해당 사례를 포함한 보고서도 원자적으로 삭제해 파생 요약을 철회할 수 있다. 보고서는 별도로 내보내거나 삭제할 수 있다. 기기 연결 해제는 토큰·목록·진행 작업을 차단하며 기존 보고서·선택 요약 삭제는 별도다.

## 적용과 결과 평가

추천별 가이드는 개인 범위, 원본 커밋, 준비 사항, 사용 예시, 확인 과제를 보여 준다. 설치 안내가 최신 브랜치를 설치하면 보고서의 고정 버전과 달라질 수 있다고 안내한다. 원본 파일과 필요한 지원 파일을 확인한 후 사용자가 설치한다. 사이트가 자동 설치·스크립트 실행을 하지 않는다.

실습 피드백은 ‘아직 사용하지 않음 / 도움이 됨 / 효과 없음’과 메모다. 자기 평가로 표시하며 실제 호출·효과 자동 관측을 주장하지 않는다. 코드·설정·PR·배포 변경은 이 기능에 포함하지 않는다.
